# Round 15 protocol: preregistered 20-seed replication of the delta win

Frozen Nov 26, 2026, before any round-15 test result is seen.
Spec: AGY's protocol (simulation-results.md section 44.3) plus Kimi's
additions (section 44.4), with the design decisions below, made by Muse
under Reza's loop order (Nov 26 16:38 PST).

## 1. Question

Does the A24 delta rule (normalised Widrow-Hoff error learning on a
fixed random reservoir) replicate on fresh seeds, with the config
selected on a validation split instead of the test set, and does it
generalise beyond the two tasks where it won in round 14?

## 2. Seeds

Seeds 201..220 (20 seeds), NOT AGY's 200..219. Reason: seed 200's
round-14-config test scores were observed during the runtime sizing
run (planted delta-256 0.243, sine delta-256 0.541, see section 9).
Using 201..220 keeps all 20 test seeds unseen. Val seeds are 201..205
(5 seeds). Train seeds are 201..220. Data seed = network-init seed
(the round-14 convention; Kimi flagged this as a confound, see 8.1).

Draw order per seed, per task:
- Planted lag-1 / lag-2 (global-RNG makers): np.random.seed(s); train
  200 seqs, val 50, test 50, in that order from one stream.
- Sine-fixed / Lorenz / var-sine (explicit-seed makers): train seed s,
  val seed s+2000, test seed s+1000 (test matches the round-14
  convention; val is a new draw).

## 3. Tasks (train / val / test sizes, K, length)

1. Planted lag-1: 200/50/50, K=16, length 24. baselines.make_data.
2. Planted lag-2: 200/50/50, K=16, length 24. baselines.make_data_lag
   (lag=2). Motifs 1-2-3, 5-6-7, 9-10-11 as in round 14.
3. Sine-fixed: 50/20/20, K=32, length 200. rpc_simple.make_sine_fixed
   (period 20 steps, phase uniform).
4. Lorenz: 200/50/50, K=32, length 24. baselines.make_lorenz
   (dt 0.01, stride 10, effective dt 0.10, range [-25, 25]). NOT
   rpc_spatial.make_lorenz (different dt/stride/range/length).
5. Variable sine: 100/20/20, K=32, length 100.
   rpc_spatial.make_sine (frequency uniform 0.02..0.08 per sequence).
   Continuous values are regenerated by the identical generator with
   the continuous sine kept (verified to reproduce make_sine's bins
   exactly); they are needed for the MSE metric.

## 4. Validation (config selection)

Grid per task: alpha in {0.7, 1.0} x smooth_sigma in {0.0, 2.0, 3.0} x
eta_d in {0.02, 0.05, 0.2} = 18 configs. Run on val seeds 201..205,
5 epochs, delta rule, n_out=256, full_code=True,
use_confirmation=False, s_inh=0.0, norm_rows=False, graded_conf=False,
unmodified p1-prototype cosine readout. Winner = highest mean val
accuracy. Tie-break: first in grid order (alpha ascending,
smooth_sigma ascending, eta_d ascending). The winner is frozen per
task and used for ALL test conditions on that task. No test data is
used for selection.

Note: alpha is the reservoir leak rate on every task. smooth_sigma
replaces the one-hot token input with a Gaussian bump centred on the
token (A14), so it is a real dimension on planted tasks too, not a
no-op: round 14's planted delta used one-hot (sigma 0), and
validation will test whether a smooth input helps or hurts there.

## 5. Test conditions (all n_out=256, full_code=True,
use_confirmation=False, s_inh=0.0, unmodified p1-prototype cosine
readout, 5 epochs, winner config per task)

1. delta (A24): learn_rule="delta", eta_d = winner eta_d,
   norm_rows=False, w_max=2.0.
2. tempcov (A25): learn_rule="tempcov", eta_d = winner eta_d,
   norm_rows=False, w_max=2.0, EMA decay 0.99. Same NLMS denominator
   and eta_d as delta, so delta vs tempcov isolates the post term
   (error p1-d1 vs centred raw post p1 - temporal mean). Clamp
   fraction is logged; a saturated clamp would invalidate the
   comparison (see 8.2).
3. burst with norm_rows=True: learn_rule="burst", eta_b=0.05,
   norm_rows=True, w_max=2.0. This is the ONLY condition with
   norm_rows on: round-14 burst collapsed to chance with norm_rows
   off, and AGY's protocol asks whether row-norm preservation
   rescues it.
4. frozen (no-plasticity control): plasticity=False, winner config.
   Still fits calibration and prototypes from train data (same as
   round 14).

Kimi's strict first-order delta ablation (delta with y2_prev
replaced by a one-step-lagged code) is NOT run in round 15: it is a
second-order design question for round 16, and AGY's four conditions
are the operative spec. Kimi's all-prefix planted metrics are
reported as m1/m2/oth (see 6).

## 6. Metrics (per task, per condition, per seed)

- All tasks: exact-bin accuracy (positions 1..end), mean_burst,
  clamp_frac (fraction of W_dist1 entries at w_max after training),
  per-seed accuracies for paired tests.
- Planted tasks: m1, m2, oth accuracies. m1 = steps where the current
  token is the middle motif element: (prev, tok) in {(1,2), (5,6),
  (9,10)}. m2 = steps where the current token completes a motif:
  (prev2, prev, tok) in {(1,2,3), (5,6,7), (9,10,11)}. oth = all
  other steps. all-motif = (m1 correct + m2 correct) / (m1 n + m2 n).
  motif_n = m2 n (matches round 14's motif_acc denominator).
- Lorenz and var-sine: also within-1-bin accuracy, continuous MSE
  (predicted bin centre vs true continuous next value), persistence
  accuracy and MSE, Markov-1/2 accuracy and MSE, ESN accuracy and
  MSE, all on the identical test sequences. ESN: baselines.ESN with
  the round-14 settings (n_res=300, ridge 1.0, see baselines.py).
- Sine-fixed and planted: Markov-1/2 accuracy on the identical test
  sequences (baselines.markov_predict, add-alpha 0.1, order-2
  backoff), and persistence accuracy.

## 7. Bars (on the 20-seed held-out test set)

Bars are judged on the lower bound of the 95% confidence interval
over the 20 seeds, unless stated otherwise (CI = mean +/- 1.96 *
std / sqrt(20), normal approximation; medians and IQRs reported
alongside).

1. Planted lag-1: delta lower 95% CI above 0.22 (target 0.25 or
   more); m1 mean at least 0.80; m2 mean at least 0.90; delta beats
   tempcov on paired per-seed differences (mean paired difference
   above 0, 95% CI excluding 0).
2. Planted lag-2: delta mean at least 0.20, and at least +0.10 above
   Markov-1 on the same test sequences.
3. Sine-fixed: delta mean at least 0.80 (matching/beating Markov-2
   0.795 on the same test sequences).
4. Lorenz and var-sine: delta beats persistence AND Markov-1 on
   exact-bin accuracy AND on MSE, with a gain of at least +0.15 over
   the frozen control on accuracy.

If a bar fails, the result is a real negative about generality, not
a protocol failure. The protocol is not re-run with different bars.

## 8. Self-critique (design decisions and known limits, frozen)

1. Seed confound (Kimi, section 44.4): data seed = network-init
   seed. The 20 fresh seeds still give an unbiased estimate of the
   config's performance, but data variation and initialisation
   variation are not separated. A future round can split them
   (same data, several inits).
2. Tempcov scale matching: tempcov uses delta's NLMS denominator
   and eta_d by design, so it isolates the post term. AGY's own
   diagnostic used an unspecified eta and reached 0.199 on planted;
   this round's tempcov may score differently. That does not matter:
   the control's purpose is the paired comparison with delta, not
   matching AGY's number.
3. Clamp: delta and tempcov both clamp W_dist1 at w_max=2.0. If
   clamp_frac is high (above ~0.05) for either rule, the clamp is
   binding and the comparison is confounded; that outcome is
   reported, not hidden.
4. The sine bar (0.80) assumes validation picks the one-hot alpha
   1.0 config (AGY's 0.847 on 3 fresh seeds). If validation picks a
   smooth config instead, the bar may fail. That is the point of the
   validation split: the bar tests the SELECTED config, not the
   best config.
5. Lorenz/var-sine bars are strict (beat persistence AND Markov-1
   on accuracy AND MSE). AGY's 1-seed checks had Lorenz failing
   persistence. If they fail at 20 seeds, that bounds delta's
   generality to noiseless deterministic token sequences.
6. What round 15 does NOT test: the omission test, the top-down
   clamp, and precision weighting (the research report's separating
   tests for predictive coding vs reservoir). Those are the round-16
   design, built after validation. Round 15 answers "does delta
   replicate?" Round 16 answers "is it predictive coding?"

## 9. Pilot numbers (timing run, NOT part of round 15)

Single-seed timing run on the VM (Nov 26, 2026, round-14 config,
seed 200): planted delta-256 acc 0.243, motif_acc 0.934, 196 s;
sine delta-256 acc 0.541, mean_burst 0.0, 291 s. These are the reason
seeds are 201..220 (section 2). They are not round-15 results.

## 10. Execution

- Driver: rpc_round15.py. Every (task, phase, config/condition,
  seed) writes one JSON line to its own results file; a worker
  skips lines already present, so a killed worker resumes cleanly.
- Validation: 5 tasks x 18 configs x 5 seeds = 450 runs.
  Test: 5 tasks x 4 conditions x 20 seeds = 400 runs.
  Total ~850 runs, ~4 min each on one CPU = ~57 CPU-hours.
- Runs on Beast (12 cores, review-venv, torch 2.15.0, numpy 2.5.4),
  10 workers (5 tasks x 2 seed-shards), ~6 h wall under normal
  load (longer while Beast is heavily loaded by the connectome
  loop). Threading: one BLAS thread per worker (OMP/MKL/OpenBLAS/
  NumExpr = 1, torch.set_num_threads(1)); the default 12 threads
  spin-wait on a loaded machine and turned a 4-min run into ~85
  min wall (Nov 26 18:24 PT). A monitor cron
  checks completion, picks validation winners, launches the test
  phase, and reports the analysis when done. No test result is
  looked at before the validation winners are frozen.
